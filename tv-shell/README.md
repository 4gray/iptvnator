# TV shell for IPTVnator (Fire TV / Android TV)

Experimental Android shell that runs the **IPTVnator browser app** (the PWA built
from this repository) on Fire TV sticks and Android TV boxes, driven entirely
with the remote, **with no server to host**: the web backend is re-implemented in
Java and embedded in the APK. _[Version française](README.fr.md)._

```
APK
├── full-screen WebView ──► http://127.0.0.1:43330/   (loopback server, NanoHTTPD)
│                              ├── /              IPTVnator PWA (assets/www, the Angular bundle)
│                              ├── /tvshell/tv.js the remote-control layer injected into index.html
│                              └── /api/*         embedded backend: M3U parsing, Xtream and Stalker proxies
└── Back / Menu / media keys → tv.js ; streams the WebView cannot play → VLC (intent)
```

> Experimental shell maintained in this repository (`tv-shell/`): it embeds the
> IPTVnator PWA built from these sources. If you redistribute a modified build
> outside the project, apply [`TRADEMARK.md`](../TRADEMARK.md) (distinct name
> and icon).

## What it does

- **Remote-control navigation**: the D-pad moves the focus between the app's
  focusable elements (a JavaScript port of Android's FocusFinder), OK activates,
  Back closes dialogs and menus then walks the history, Menu opens the focused
  item's context menu, play/pause/rewind/fast-forward drive the video. Virtual
  lists of thousands of channels work (scroll, then look again).
- **M3U playlists by URL, Xtream Codes portals, Stalker portals** through the
  embedded backend: the same route contract as `apps/web-backend`, with the M3U
  parser ported line by line and checked against 43 fixtures generated by the
  real JavaScript parser (`tools/gen-parser-fixtures.mjs`, verified in CI).
- **Playback** with the PWA's own players (HLS `.m3u8`, MP4, DASH ClearKey) in
  the WebView. Streams a browser cannot play (raw `.ts`, AC3 audio...) trigger
  a **"This stream cannot be played here"** prompt offering to open them in
  another player (VLC, Kodi, MX Player...). The app's "Copy stream URL" button
  does the same on a TV.
- **Shell settings** (long-press Menu, or hold Back on remotes without a Menu
  key): interface size (960 / 1280 / 1600 px), preferred external player, data
  reset, diagnostics (WebView version, screen).
- Data (playlists, favourites, positions) is stored by the PWA in the WebView
  (IndexedDB / localStorage) and survives restarts and updates. The embedded
  backend has no server storage: it answers the PWA's `/api/v1/instance` probe
  with 404, the answer of a backend without it.

Inherited PWA limits: no EPG/XMLTV, no downloads, no embedded MPV (desktop-only
features in IPTVnator).

## Security model

- The embedded server listens on `127.0.0.1` only (`TvShellServer`): nothing is
  exposed on the LAN. `/api` request bodies are capped at 16 KiB (413), the same
  bound as the upstream web backend, and provider URLs must be `http`/`https`.
- Provider requests follow at most five redirects; `Authorization`, `Cookie`,
  `Proxy-Authorization`, `SN` and `Host` are dropped when a redirect leaves the
  origin, exactly like the web backend's `ValidatedHttpClient`.
- The WebView has file and content access off; the only top-level navigations
  that leave the shell are `http(s)` links handed to the system (`ACTION_VIEW`),
  any other scheme is ignored. The `window.TvShell` bridge only exposes the
  shell's own actions (ready, external player, toast, keyboard, settings, exit).
- The published APK is a **non-debuggable** release build, `allowBackup` is
  off (the WebView storage holds portal credentials) and remote debugging
  (`chrome://inspect`) is **opt-in** in the shell settings.
- Cleartext traffic is allowed on purpose: the app's own origin is
  `http://127.0.0.1` and most IPTV portals and streams are plain `http`.
- Known limitation: any other app on the device can reach the loopback server
  and make it fetch provider URLs. There is no secret between the WebView and
  the server yet.

## Building the APK

### With GitHub Actions (recommended)

The `Build TV shell APK` workflow runs on pull requests and `master` pushes that
touch `tv-shell/` (artifact only) and on demand (**Actions → Build TV shell APK
→ Run workflow**; tick `create_release` to also publish a GitHub release
`tv-shell-v0.1.0-N`). The release is a **pre-release never marked "Latest"**
unless you untick `prerelease`: keep it on in the IPTVnator repository itself,
where a Latest release without the desktop updater's files would break
auto-update; a fork publishing for its own users can untick it. It builds the PWA
(`pnpm nx build web --configuration=pwa`, as the Docker image does), checks the
parser fixtures against the installed parser, drives that PWA with the two
remote-control suites in Chromium (screenshots are uploaded when one fails),
runs the backend tests, assembles the release APK and uploads
`iptvnator-tv-shell-0.1.0-<sha>.apk`.

Signing: without secrets the APK is signed with the **versioned debug key**
(`android/app/debug.keystore`, password `android`), which is conventional, not
secret, and stable across builds, so newer builds install over older ones. Add
the `TVSHELL_KEYSTORE_B64` (base64 keystore), `TVSHELL_KEYSTORE_PASSWORD`,
`TVSHELL_KEY_ALIAS` and `TVSHELL_KEY_PASSWORD` secrets for a release key. The
`versionCode` is the commit time in minutes, so every build upgrades the
previous one.

### Locally (Android Studio or the command line)

```bash
# 1. the PWA, from the repository root
pnpm install --frozen-lockfile --ignore-scripts
pnpm nx build web --configuration=pwa
# 2. copy it into the shell
tv-shell/scripts/bundle-pwa.sh dist/apps/web
# 3. the APK (JDK 17 + Android SDK; Android Studio provides both)
cd tv-shell/android && ./gradlew :backend:check :app:assembleRelease
# → app/build/outputs/apk/release/app-release.apk (signed with the debug key)
```

## Installing on a Fire TV stick

1. **Settings → My Fire TV → Developer options**: enable *Apps from unknown
   sources* (or *Install unknown apps → Downloader*) and, for ADB, *ADB
   debugging*.
2. **Downloader**: install the *Downloader* app from the Appstore, enter the
   APK's URL from the GitHub release (right-click the `.apk` asset → copy
   link), install.
3. **ADB** (from a PC on the same network):
   ```bash
   adb connect 192.168.x.x        # the stick's IP: Settings → My Fire TV → About → Network
   adb install -r iptvnator-tv-shell-0.1.0-xxxxxxx.apk
   ```
4. Start *TV Shell for IPTVnator*. Add a source: **Sources → Add M3U / Add
   Xtream / Add Stalker**; OK on a text field opens the Fire TV keyboard.
5. Install **VLC for Android** (Appstore) for `.ts` streams.

## Remote keys

| Remote | Action |
| --- | --- |
| D-pad | move between elements; on the picture: ◀ ▶ seek, ▲ ▼ leave the picture / reach the controls; in a text field the arrows move the caret until it cannot move further |
| OK | activate; on the picture: fullscreen; on a text field: keyboard. A held OK is one activation |
| Back | close dialog/menu → leave fullscreen → previous page → (twice) exit the app; **hold**: shell settings (remotes without a Menu key) |
| Menu | context menu of the focused item; on the picture: open the stream in VLC; **long press**: shell settings. The HDMI-CEC context-menu key and Y on a game controller do the same |
| ▶⏸ ⏪ ⏩ | play/pause, −15 s, +30 s |

## Design notes

- No LAN server: the backend is embedded in Java (`WebBackend`) with the same
  contract as `apps/web-backend` (provider-targets / parse / xtream / stalker).
  `/parse-xml` deliberately answers 501: the PWA does not show the EPG.
- Fixed origin `http://127.0.0.1:43330`: the PWA's storage belongs to the
  origin, so the port of the first start is remembered and never replaced.
  When another app holds it, the shell retries it briefly, then serves on
  another port (43330 to 43334) for that run only and says so in a toast and
  in the diagnostics; the next start returns to the user's data.
- The Angular service worker is not served (deliberate 404): the bundle ships
  inside the APK, caching would only make updates stale.
- `tv.js` is loaded **before** the bundle through a same-origin
  `<script src="tvshell/tv.js">` tag (the app's CSP forbids inline scripts). No
  IPTVnator file is modified. It calls `TvShell.onReady()` only once Angular has
  rendered; the shell shows the error panel with the diagnostics when that does
  not happen within 30 s or when the page reports an `Uncaught SyntaxError`.
  The 30 s wait doubles once while the page is still being fetched (a cold
  start after an update), starts again when the bundle has run (Angular's
  bootstrap gets its own period), and pauses while another app is in front (the
  page's timers are paused then). A main-frame load error from the loopback
  server is retried once after the server is restarted, an HTTP error from it
  opens the panel at once, and the splash (with the credits) stays at least
  1.5 s. While the panel is up, the remote's keys always land on its buttons.
- The WebView is created in code, not inflated: when the system WebView is
  missing, disabled or being updated, the error panel says so instead of the
  app crashing at start.
- The screen is kept on only while a `<video>`/`<audio>` plays (and during the
  splash): `tv.js` reports `playing`/`pause`/`ended`/`emptied` to the shell, so
  the screensaver and the device's sleep work on lists and menus.
- After Android closes the app in the background, it reopens on the route it
  was showing (saved instance state; the server's SPA fallback serves any route).
- Layout width 1280 CSS px (960 / 1600 selectable) with the page scale pinned
  from the measured screen width (`DisplayMetrics`; a 1080p Fire TV is 960 CSS
  px wide, so the scale is 0.75): the WebView's own overview-mode fit proved
  unreliable on the device.
- The WebView renderer may be killed on a 1 GB device: `onRenderProcessGone`
  recreates the Activity (the server survives in the Application); three
  crashes, or deaths while the app is in front, within a minute show the error
  panel instead of looping. The system reclaiming the hidden renderer while VLC
  or another app is in front does not count.
- Memory on a 1 GB device: provider answers are capped at an eighth of the app's
  heap (64 MB at most, about 32 MB on a Fire TV Stick Lite) and refused before
  download when the declared size is larger (`ERR_RESPONSE_TOO_LARGE`). Xtream
  and Stalker JSON answers are validated and passed through verbatim instead
  of being rebuilt as maps; responses are encoded straight to UTF-8 bytes and
  the M3U parser walks the text without splitting it into a second copy.
- The loopback server never lets an `Error` reach Android's default handler
  (which kills the app): request bodies are read directly (no NanoHTTPD temp
  file, whose failure is a bare `java.lang.Error`), a request thread that cannot
  be started drops that connection only, and an `Error` on a request thread ends
  that request.
- Engine requirements measured on the shipped bundle: the JavaScript needs a
  Chrome ≥ 94 engine (class `static {}` blocks), the CSS looks right from
  Chrome 111 (`color-mix()`). The Fire TV Stick (Fire OS 7) ships a recent
  Amazon WebView and runs the bundle.

## Developing and testing on a PC

```bash
# reference backend in Node + mock provider (Xtream user/pass, M3U) serving a built PWA
WWW=/path/to/dist/apps/web tv-shell/devserver/run-dev.sh        # http://127.0.0.1:43330
# in a browser: F9 = Back, F10 = Menu, F8 = Play/Pause, F7 = external player
# remote-control tests (Playwright, also run by the workflow) against the dev server
node tv-shell/tests/tv-remote.mjs ; node tv-shell/tests/tv-longlist.mjs
# the real Java backend on the JDK, without Android (same classes as the APK)
cd tv-shell/android && ./gradlew :backend:check
# regenerate the parser fixtures after an iptv-playlist-parser upgrade
node tv-shell/tools/gen-parser-fixtures.mjs
```

## Structure

```
tv-shell/
├── android/                 Gradle project
│   ├── backend/             pure-Java library: M3U parser, /api routes, Xtream/Stalker helpers (+ JVM tests)
│   └── app/                 Android app: NanoHTTPD server, WebView, settings, JS bridge, external player
│       ├── debug.keystore   versioned debug signing key (password "android")
│       └── src/main/assets/tvshell/   tv.js (the remote-control layer) and THIRD-PARTY-NOTICES.txt
├── devserver/               reference backend in Node + mock provider, to develop and test on a PC
├── tests/                   Playwright tests: driving the real app with remote keys
├── tools/                   parser fixture generator (from the real JS parser)
└── scripts/bundle-pwa.sh    copies the built PWA into the assets
```

## Status and limitations

- Experimental; tested on a Fire TV Stick Lite (Fire OS 7, 1 GB). Generic icon
  and banner; `versionName` is bumped by hand.
- Only `http`/`https` provider URLs; no EPG, downloads or embedded MPV (PWA
  limits).
- Playlists and portal answers larger than an eighth of the app's memory (about
  32 MB on a 1 GB stick) are refused with `ERR_RESPONSE_TOO_LARGE`.
- The loopback server is reachable by other apps on the device (see the
  security model).

## Troubleshooting

The **diagnostics** (long-press Menu or hold Back → Shell settings, or the error panel) show
the WebView's Chrome engine version, the device, the embedded server port and a
"Screen" line (pixels, density, CSS width, layout width). Attach it to any
report. From a PC:

```bash
adb connect 192.168.x.x
adb logcat -s TvShell chromium          # [console] = page errors; "web app ready" = the app started
adb shell dumpsys package com.amazon.webview.chromium | grep versionName
```

### Installation

- **"App not installed" / `INSTALL_FAILED_UPDATE_INCOMPATIBLE`**: the installed
  APK was signed with another key (a local build, another fork). Uninstall it
  first (Settings → Applications → Manage installed applications, or
  `adb uninstall org.tvshell.iptvnator`); builds from this repository share one
  key and update each other with `adb install -r`.
- **Downloader refuses to install**: enable *Apps from unknown sources* (or
  *Install unknown apps → Downloader*) in Developer options and use the direct
  `.apk` link of the release.
- **`adb connect` refused**: enable *ADB debugging*, accept the prompt on the TV
  at the first `adb` command; the IP is under About → Network.

### Start-up

- **"The player could not be loaded"** after 30 to 60 s: the page did not start. If
  the Chrome version shown is below **94**, the WebView cannot run the Angular
  bundle; update "Amazon WebView" / Android System WebView from the Appstore
  (GeckoView would be the fallback). Between 94 and 110 the app works with
  degraded colours. The last console error is shown under the message.
- **"The system web view is unavailable"**: Amazon WebView / Android System
  WebView is being updated or was disabled. Wait a minute and press Retry, or
  update (re-enable) it.
- **"The embedded server could not start"**: ports 43330 to 43334 are taken by
  another application; close it or restart the stick. The chosen port is
  remembered because the app's data is bound to `http://127.0.0.1:port`.
- **"Port 43330 is used by another app"** toast, empty app: this run uses a
  temporary port, so the saved playlists are not visible. Close the other app
  (or restart the stick) and reopen; nothing was lost.
- **"The player was restarted after it ran out of memory"**: the WebView's
  renderer was killed; the app reloads from its start view (the last view only
  when IPTVnator's start-up setting restores it). If it keeps happening, use a
  smaller playlist (hide categories in IPTVnator). After Android closed the app
  in the background, it reopens on the page it was showing.

### Display

- **The picture does not fit the screen, or is too small**: the scale is
  `CSS width ÷ layout width` (on a 1080p Fire TV: 960 ÷ 1280 = 0.75). Check the
  "Screen" line of the diagnostics and change *Interface size* (960 = large,
  1280 = normal, 1600 = dense). If it is still cut off, report the "Screen"
  line and the build.

### Remote

- **A key does nothing**: `adb shell getevent -l` shows the code the remote
  sends; the intercepted keys are listed in `MainActivity.dispatchKeyEvent`
  (Back, Menu and its aliases, play/pause, rewind, fast-forward), everything
  else goes to the page (`tv.js`).
- **No Menu key** (Google TV, most Android TV boxes): hold Back for the shell
  settings.
- **No visible focus**: press an arrow, the remote layer puts the focus back
  near its last position. Back closes dialogs and menus first, then walks the
  history, then exits (two presses).
- **No keyboard on a field**: OK on the field opens the Fire TV keyboard;
  otherwise `adb shell input text "..."`.

### Playback

- **Silent / black stream, "This stream cannot be played here"**: codec or
  container the WebView does not handle (raw `.ts`, AC3...). Accept the VLC
  prompt (install VLC from the Appstore), or Menu on the picture / "Copy stream
  URL". For Xtream, choose the `m3u8` output format in the playlist settings.
  Each new attempt on a channel asks again.
- **The VLC prompt no longer appears**: Shell settings → *External player* →
  tick "Offer an external player" and pick the player. A dropped connection
  (media error 1 or 2 from the browser player) does not offer it: VLC would
  fail the same way.
- **"Error, something went wrong (ERR_RESPONSE_TOO_LARGE)"** when adding a
  source: the playlist or portal answer is larger than the device can hold; use
  a smaller export (one country, no VOD) or an Xtream portal.
- **The screensaver starts on a list**: intended; the screen stays on while a
  stream plays.

### Data and memory

- **Start over**: Shell settings → *Erase IPTVnator data* (or uninstall the
  app). Data survives updates as long as the server port does not change.
- **Inspect the page**: Shell settings → *remote debugging*, then
  `chrome://inspect` on a PC with `adb connect`.
